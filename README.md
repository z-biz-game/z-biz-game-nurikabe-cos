# 数墙 Nurikabe · 岛与墙的推理

`N×N` 的盘上，数字写着它所在那座白岛有几格，剩下的格子全归一整块黑墙。这里出货的每一盘都只有
一个答案，也每一盘都能用七条局部推理从空盘一路推到底——一次都不许靠猜。

本文里的数字只有两类来源：仓里读得到的代码（写成 `文件:行号`），和 2026-09-28 那一次全绿跑出来的
读数。跑的命令是 `npm run check`、`node tools/engine-test.mjs`、`SAMPLES=24 node tools/balance.mjs`、
`bash tools/verify.sh`，环境 Node v26.8.1 / macOS。引擎断言与 `npm run check` 是当场重跑的，
难度分位表与浏览器门禁的读数是那次全绿会话的输出，逐条列在下面。

**代码 > 本文档**：本文与 `js/`、`tools/` 冲突时，以代码和它跑出来的输出为准。

## 规则（玩家视角）

三条规则就是菜单里那段说明的原文（`index.html:53-58`，Nikoli 口径）：

1. **数字即岛**：数字 N 所在的白岛，连数字格自己一起算，恰好 N 格；一个岛里只有一个数字，岛内四连通。
2. **墙是一整块**：所有黑格必须四连通，成一整片海，不许分出第二块。
3. **二二不全黑**：任何一个 2×2 里，四格全黑就是撞了规则。

- 一格只有三种状态：未定 / 白（岛）/ 黑（墙）。这里没有铅笔标记那种东西——数墙的答案只有两种
  颜色，写下颜色就是落子；单击按「未定 → 白 → 黑 → 未定」循环（`js/engine/nurikabe.js:712-718`），
  而写着数字的那一格永远涂不黑（`js/engine/nurikabe.js:705`）。
- 判胜不另起口径：`complete()`（`js/engine/nurikabe.js:563-565`）就是"`verify()` 一条问题都没有"
  且"没有一格还是未定"。而 `verify()`（`:535-561`）只读盘面、按上面三条的原文逐字查，
  绝不读引擎自己写下的中间结论（`:535-536`）——提示逻辑写错，伪造不出一场胜利。

## 怎么玩

- 五档：初学 5×5、熟手 6×6、常规 7×7、高手 8×8、大师 10×10（`js/engine/generate.js:35-91`），
  外加按天换题的日课：日期经 `dailySeed` 变成种子，档位再按天序轮换，两者都确定
  （`js/main.js:468-473`、`js/engine/rng.js:63-66`）。
- 落子：拖动连续落子，从同色上起笔就是擦；`1` 墙、`2` 岛、`M` 换模式、`H` 提示、`Z` 撤销
  （`index.html:129`）。一整笔算一条撤销记录，不是每格一条（`js/main.js:567-576`）。
- 提示是"下一步可证的事实"：它说出哪一格必须是什么、凭七条里的哪一条，并替你把那一格落下
  （`js/ui/game.js:229-242`）。落下的那一格在盘面的**每一个解**里都成立，所以提示不会把你带进歧路。
  你自己已经画反了的时候，提示拒绝落子、也不计费（`js/ui/game.js:209-228`、`js/main.js:582-589`）。
- 侧栏八个读数（步数 / 提示 / 已定 / 未定 / 凑满的岛 / 墙块数 / 冲突 / 难度实测，
  `index.html:105-114`）全部由引擎现算，不是界面自己数格子；「凑满的岛」「墙块数」只有**没达成**时
  才变红（`js/main.js:260-262`）。开局空盘满屏红框这种事是被明确禁止的，理由写在
  `js/engine/nurikabe.js:580-581`。
- 存档只有一份、一个键 `nurikabe.save.v1`（`js/store.js:8`）：接着上次那盘继续，或者「清空存档」
  从头来（内存与磁盘两边一起清，`js/store.js:197-202`）。

## 这个仓**不承诺**什么

- **不承诺「唯一解 ⟹ 铅笔推得完」**。七条规则不完备，反方向不成立：`reachable()` 逼不出矛盾只说明
  没找到反证，它从不说"这样放是对的"（`js/engine/nurikabe.js:524-526`）。有些唯一解的盘这里就是
  推不完——那正是生成器要丢掉的东西，不是漏网的答案。
- **不承诺出题耗时**。五档出题墙钟 p50/p90/p95（ms）：初学 1.6/3.4/4.8 · 熟手 3.1/5.5/6.4 ·
  常规 6.9/29.7/38.8 · 高手 23.6/48.6/58.2 · 大师 106.8/338.5/558.9，出题合计 4.9s、
  端到端 5.0s（含逐题复解重验与穷举对账）。分布是双峰的，所以 `tools/balance.mjs` 只把它打到
  stderr、不设 `budgetMs` 门禁：「双峰分布的中位×2 是假的天花板」是它自己的注释写的（`:23-25`，
  表头 `:212`）。在这里写一个绝对毫秒预算就是假承诺，真正进 stdout 闸的是确定性的穷举节点数尾巴。
- **不承诺每格分单调**。五档每格分 p50 是 1.500 / 1.514 / 1.541 / 1.492 / 1.465（下表），
  原始分递增里有尺寸贡献。这条 caveat 是 `tools/balance.mjs:206-208` 自己印在输出里的，不是我的免责。
- **不承诺线索最少**。`pruneClues` 是贪心删，不保证删到不能再删；它只保证"删完还能推完"
  （`js/engine/generate.js:239-243`）。"线索最小"从来不是承诺。
- **没有烘焙题本**。仓里没有 `js/data/`，`package.json:11` 的 `npm run bake` 指向并不存在的
  `tools/bake.mjs`，那条命令现在是红的。`.github/workflows/ci.yml:27-34` 把它点名为唯一还缺的
  那道闸——缺就写明缺，因为"检查一个不存在的东西"的绿是谎话。每一局都是现场出的题。
- **有代码、但浏览器闸没断言过的分支**：「线索推完而盘未满」的 `stalled` 文案
  （`js/ui/game.js:245`、`js/main.js:590-595`）与状态行那句 `stuck`（`js/main.js:223`，
  它来自 `js/ui/game.js:104` 的 `reachable()`）。出货盘必然推得完，正常玩法碰不到这两句；
  `tools/scenarios.js:577` 只把"提示走到 stalled"当成跑题失败来处理，
  并没有断言这两句话长什么样、渲染在哪。
- **只在本地 headless Chrome 里绿过**。Safari、Firefox、真机 iOS/Android、低配设备、以及
  `prefers-reduced-motion` 之外的键盘与读屏无障碍都未经验证。
  `bash tools/verify.sh` 跑的是本机 root 形态与本机带 `/z-biz-game-nurikabe-cos/` 前缀的两种 URL
  （两种形态各 755 条，2026-09-28 实测）。线上那一种也跑过：
  `BASE_URL=https://z-biz-game.github.io/z-biz-game-nurikabe-cos/ bash tools/verify.sh` 交出同一套
  9 个场景、**755 条、0 失败、20 秒**（2026-09-28 04:56，跑的就是 push 之后 Pages 上那份部署件，
  脚本因此不起任何本地服务，只连一个 headless Chrome）。仍未验证的是浏览器种类与设备。
  部署工作流是无构建的文件拷贝（`.github/workflows/pages.yml`）。
- Electron 壳（`electron/main.cjs`）只有 `npm run check` 的 `node --check` 级检查，没有任何运行时断言。

## 难度是量出来的

分数 = Σ(规则权重 × 该规则在这盘出手的次数) + 0.5 × 回扫轮数（累加在 `js/engine/nurikabe.js:490`，落到返回值是 `:502`；
口径同步写在 `js/engine/generate.js:282-287`）。它是**规模相关**的量，所以同尺寸之间才谈"更费脑子"，
跨档比较必须同时看每格分。

`SAMPLES=24 node tools/balance.mjs` 那一次的输出（`exit 0`；band 不参与出题筛选，
`balance.mjs:79` 传的是 `band: null`，入带率是事后结算）：

| 熟手 | 6×6 | 51–63 | **54.5** | 1.514 | 36 | 2 | 2/3/4/5 | 100% | 160 / 375 | 8 |
| 常规 | 7×7 | 71–82 | **75.5** | 1.541 | 49 | 3 | 2/4/5 | 100% | 254 / 3671 | 11 |
| 高手 | 8×8 | 89–110 | **95.5** | 1.492 | 64 | 3 | 2/3/4/5 | 100% | 491 / 2541 | 14 |

- 「深度」是那一批样本各自**最深动用到的规则层级**的集合（`topTier` 的取法
  `js/engine/nurikabe.js:494-495`，聚合 `tools/balance.mjs:93`）。常规档那一次只出现 2/4/5，
  是因为 24 个样本里没有哪盘的最深一步落在第 3 层——这一列是观测集合，不是配置。
- 五档的出场规则**全部七条都在场**（`balance.mjs:156` 那一行的实测口径），闸要求每档至少动用
  3 条（`:199`），不然分数只剩盘尺寸在撑。
- 步数 p50 恰好等于格数（25/36/49/64/100）：出货盘的铅笔路径每格恰好写一次，这条在
  `tools/engine-test.mjs` 的端到端一节里被逐档钉住（`eq(g.steps, b.n, '步数 = 格数（每格恰好一次）')`）。

这道门槛是被拒收的盘撑起来的。那一次运行的拒绝统计（`balance.mjs:161-175`）：

`tools/balance.mjs:175` 对这一行的原话是「难度阶梯就是被这个拒收率撑起来的」。

## 七条铅笔规则（提示只会说这些）

顺序是 `RULE_ORDER`（`js/engine/nurikabe.js:213`），权重按"这条推理要看见多少盘面"定价：

| # | key | 名字 | 层级 / 权重 | 它在说什么（提示文案的原型，`js/engine/nurikabe.js:154-211`） |
|---|---|---|---|---|
| ① | `number` | 数字即白 | 1 / 1 | 这格写着 N，它自己就是岛的一格，只能白 |
| ② | `full` | 满岛圈墙 | 2 / 1.5 | 岛已凑满 N 格，四周未定的再涂白就成 N+1 格了，只能全黑 |
| ③ | `clash` | 两岛相逼 | 3 / 2 | 这格一白就把两座岛并成一个，只能黑 |
| ④ | `reach` | 够不着即黑 | 2 / 1.5 | 这格到最近还没满的岛还差 k 格，那点空位装不下它，白格没有岛可去 |
| ⑤ | `three` | 三黑补白 | 2 / 1.5 | 那个 2×2 已经黑了三格，第四格必须留白 |
| ⑥ | `fill` | 岛地必满 | 4 / 2.5 | 岛要 N 格，而周围没被墙围死的格子恰好只剩 N 格，这一片必须全白 |
| ⑦ | `bridge` | 孤墙必连 | 5 / 3 | 这格一涂白，两片墙就永久断开：它是桥，必黑 |

七条都只查局部的账：每一步写下的格子，对盘面的**每一个解**都成立（`index.html:60-62` 那句
"所以'推得出'和'必定对'是同一件事"就是这个意思），所以"铅笔推得完 ⟹ 解唯一"是数学上的必然。
反向不成立，见上面「不承诺」。`js/engine/generate.js:10-12` 顺带写清了第 ④ 步（穷举对账）为什么
不是多余的仪式：它盯的是"规则实现有没有写错"这件事本身。

引擎里还有一步 `consolidate`（`js/engine/nurikabe.js:215-248`）：那是岛归属的**记账**，
不算规则、不进权重，所以它不会出现在提示文案里。

## 跑测试：六条命令各自证明什么

```bash
npm run check              # 逐文件 node --check：全部 js + server.cjs + electron + tools。OK
```

  B 七条铅笔规则的手推锚点｜C 规则可靠性模糊测试（全枚举对账）｜D1 矛盾检测｜
  D2 状态机：落子 / 循环 / 撤销｜D3 生成器：出货的盘必须零猜测 + 唯一解｜E 随机数与日课种子。
  报告里的每节计数是**累计**口径（19 → 39 → 154 → 165 → 185 → 242 → 425 → 438），
  由测试文件自己加总，不是手抄（`.github/workflows/ci.yml:41-42` 写的就是这条纪律），总数 438（2026-09-28 重跑）。
- C 那节是这套承诺的地基：4×4 的 `2^16` 种涂法全枚举出合法完整盘（代码要求 3000 块以上，
  `tools/engine-test.mjs:423-432`），用显式种子 `fuzz.v1` 抽 900 盘（`:434`、`:444`），
  每条铅笔结论必须在穷举出的**每一个解**里都成立。五个"必须是 0/必须相等"的计数：
  不可靠结论、把有解盘判成矛盾、推完了而穷举说解不唯一、铅笔答案与穷举答案逐格不同、
  剪枝版与傻跑版解数不同（`:488-492`），再加七条规则全部被真实触发到（`:493`）。
  另有一轮"带墨水的盘"同样口径的复核（`:496-533`）。
- D3 是五档端到端：每档现场出题（种子 `e2e`，`tools/engine-test.mjs:800`），
  断言 `g.steps === b.n`「步数 = 格数（每格恰好一次）」（`:820`），
  难度分还能从 `breakdown` 逐条规则重算回去。
- `balance` 的 stdout 是逐字节可复跑的（`diff <(node tools/balance.mjs) <(node tools/balance.mjs)` 为空，
  种子写成 `scn|<档>|<i>` 的显式串，`balance.mjs:75`；墙钟走 stderr）。测的是**不筛带**的原始分布。
- `verify.sh` 的九个场景按顺序是 `first zero hint conflict save resume daily layout narrow`

  前缀那一跑才是「换了文档目录」，不是「重装一遍」」是它自己写着的（`:97`，CI 侧同一条理由在

- `verify.sh` 里有一步"node 重算种子指纹"（`:139-194`）：九行手抄的期望指纹
  （`tools/scenarios.js:20-66`）在 node 里重算一遍，再和浏览器里读到的同一张盘对拍——
  同一颗 seed 必须在 node 和 Chrome 里画出同一张盘。
- CI（`.github/workflows/ci.yml`）两个 job：`check` = `npm run check` + 测试脚本自身语法 +
  `engine-test` + `SAMPLES=24 balance` + 入口文件 grep + `doctest` + `sabotage`；`browser` = Node 22 上 `bash tools/verify.sh`。
  **全程没有 `npm install`**：零运行时依赖、零构建步骤，装依赖只会换来网络抖动。
  `node-version: 22` 是被 `tools/playtest.cjs` 钉的——它用 22+ 才有的全局 `WebSocket`/`fetch`。
  `doctest` 与 `sabotage` 是纯 node 逻辑闸（不起浏览器、不开端口），CI 的 `check` job 和本地
  `bash tools/verify.sh` 跑的是同两条命令——本地绿 == CI 绿，没有"只在某一边才跑"的那道。
- `file:NN` 引用在 `doctest` 里有两条腿。D11 问"这个行号落在真实文件的行数内吗"；D18 问"被指的那几行里，
  真坐着这句话点名的那个东西吗"。后者拿同一份文档当输入现推锚点：贴着 `path:NN` 写出来的那个反引号标识符
  就是锚点，一条锚点是 (文件, 行段, 名字) 这个三元组，同一处在两份文档里各写一次只算一条。本轮现推锚点 17 条，
  逐条落回原处；这一格上线当轮改掉的是 `DESIGN.md` §3 里那句把 `OVERBUDGET` 与 `UNIQUE` 混引到同一行的话
  （两个状态在 `js/engine/count.js` 里本来就差两行）。
  **这条腿没覆盖什么也写在这**：文档里还有大量句子里没有贴着标识符的裸 `path:NN`，现推腿对它们一条都拿不到，
  那些仍只过 D11 的范围检查；D18c 那把刀下在内存里（把某句引用的行号整段挪两行，盘上一个字节不动），
  它证明的是"挪错了会红"，不是"每一句都被核过"。

## 破坏试验台账（4 把刀）

`tools/doctest.mjs` 绿了，"绿"也有两种：被断言真的守住了，和解析器集体扑空（正则改了形状、锚点被
删空、balance 压根没跑起来）。前者是成绩，后者是假账。唯一的分辨办法是把"文档抄了一个已经不存在的
数"这类谎一类一类塞回**代码**里，看这道闸是不是立刻变红、并且红的就是文档点名的那一条。
`tools/sabotage.mjs` 就固化了这四把刀：每把改一个真实代码文件、当场跑 doctest 读回真实 rc、再用内存
里读回的原始字节 `writeFileSync` 复原（绝不借 git 命令复原），复原后逐字节回读校验；最后不带破坏地对照
跑一遍 doctest + engine-test，证明台账不是靠把闸改坏来让自己变绿的。

| 刀 | 打哪一组 | 它把什么改坏 | 必须逼红的那条断言 | 真实 rc |
|---|---|---|---|---|
| K1 | D1 | `generate.js` 初学档 band 上限 43→42 | 「D1 初学 的 band 34–43 == TIERS 现值」 | 1 |
| K2 | D2 | `nurikabe.js` 第 7 条规则 bridge 权重 3→2 | 「D2 bridge 的层级/权重 5/3 == Rules 现值」 | 1 |
| K3 | D7 | `verify.sh` 的 HTTP 默认端口 5311→5312 | 「D7 HTTP 默认号两处一致」 | 1 |
| K4 | D8 | `index.html` 第一个读数单元 class 改掉（侧栏只剩七个 stat） | 「D8a index.html 解析到 N 个 stat 单元」 | 1 |

每一格的 rc 都是 `node tools/sabotage.mjs` 从子进程读回来的真实读数（不是抄的），自钉回脚本里；干净树
上重跑只会得到同样的 1，是幂等的。任何一把刀塞了谎 doctest 却仍 rc=0，或红在了别处，台账自己就判红。

## 技术形态

- **零运行时依赖、零构建步骤**：纯 ES Module + 一块 `<canvas>` + WebAudio 合成音
  （`js/audio/synth.js`）。`dependencies` 是空的，`devDependencies` 只有 `electron`，
  浏览器代码里没有一行 import 它。
- **零美术与音频文件**：岛纸、墙的云纹（由格号决定，不是随机噪点，`js/render/board.js:22-32`）、
  数字、绿环、红框、favicon（`index.html:10` 的 data URI，否则浏览器会去 Pages 域名根上探
  `/favicon.ico` 白留一条 404）全部现画。
- **DOM 是状态的复述，只有一处同步点**：所有改动入口最后都走 `afterChange()`（`js/main.js:548-554`），
  连"帮我把这盘推完"也不例外（`js/main.js:629-639`）。
- **存档一个键** `nurikabe.save.v1`：盘本身不进存储（存的是**原点 seed**，`js/store.js:170-171`），
  墨走 RLE（`js/store.js:17-48`）；每个字段过 `shapeOf`/`sanitize`（`:77-108`），
  墨与盘面对不上数就**整份丢掉**（`:41-42`），`localStorage` 整个儿抛异常（隐私模式）也照样能玩，
  `reset` 内存与磁盘两边一起清（`:197-202`）。10×10 的存档一两百字节。
- **布局问的是容器，不是视口**：`#app { container-type: inline-size }` +
  `@container (max-width: 860px)`（`css/game.css:31`、`:440-442`），画布边长由 `.stage` 内容盒
  与视口高一起定（`js/main.js:139-169`）。细节与踩过的坑在 `DESIGN.md` §7。
- 规模：10 个运行时 ES Module + 5 个验证脚本 + 静态服务与 Electron 壳，浏览器侧约 4100 行、
  验证侧约 3000 行；引擎断言 438 条、浏览器断言 755 条/形态，均为实测（出处见上）。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`26`）与这一次跑的断言条数（`44`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`26`、断言仍然 `44`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
